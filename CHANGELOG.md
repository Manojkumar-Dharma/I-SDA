# Changelog

All notable changes to iSDA, latest first. One line per version: what changed and why.
Detail lives in `git log` (each version has a matching commit); features in
[`README.md`](README.md); tracked work in
[`docs/sda-reference/keywordFixes.md`](docs/sda-reference/keywordFixes.md) (`I-` keyword
audit) and [`docs/sda-reference/LIMITATIONS-PLAN.md`](docs/sda-reference/LIMITATIONS-PLAN.md)
(`L`/`M`/`P`/`S36-` tasks).

Task prefixes: **I** keyword-compliance audit · **L**/**M** designer fixes and features ·
**P** New UI · **R**/**D** picker foundation · **S36** DSPF36 / S/36E.

## 0.10.79 and later — Keyword-compliance audit (I-series) and follow-ups

- **0.10.260** — I-135 (Record; `SETOFF` as the documented alias of `SETOF`): the DDS Reference says SETOFF "is equivalent to the SETOF keyword" (SETOF preferred, option indicators not valid), but only SETOF was handled. SETOF's `keywordSpec.js` record-indicator fact now lists `alternateNames: ['SETOFF']`, so a hand-written SETOFF reads as a Set off row in the Define Indicator Keywords panel (and is written back as SETOF, like ROLLUP / ROLLDOWN), the SFL / SFLMSG / PDNSFLCTL indicator-text rows read and replace it via a new `withAlternateSpellings` helper, and a new SETOFF `noOptionIndicators` fact makes the guard refuse option indicators on it. New `i135SetoffAliasOfSetof.test.js` (25 checks); three older tests updated for SETOFF as the 96th table entry. Full suite: 209 files, 11,786 checks, zero failures.
- **0.10.259** — I-121 (Cross-level; record-indicator keyword group slice): the ten kinds of the record-level Define Indicator Keywords panel (CLEAR, PAGEDOWN, PAGEUP, HOME, HELP, HLPRTN, VLDCMDKEY, SETOF, CHANGE, INDTXT), their ROLLUP / ROLLDOWN spellings and the webview's four no-conditioning kinds were hand-kept in the writer and the webview; they are now one `RECORD_INDICATOR_KEYWORDS` fact table in `keywordSpec.js` (`alternateNames`, `ddsReference`) with `KeywordSpec.recordIndicatorKeywordNames` / `recordIndicatorAlternateKinds` / `recordIndicatorTakesOptionIndicators`, the last derived from the existing `noOptionIndicators` fact so the two cannot drift. Pure refactor - derived values equal the old literals, checked in the new `i121RecordIndicatorGroupKeywordSpec.test.js` (49 checks). Logs one deferred finding (`SETOFF`, equivalent to `SETOF`, is not read by the panel). Full suite: 208 files, 11,760 checks, zero failures.
- **0.10.258** — P15 (Compare/overlay; window interiors hide what is under them): in a stacked multi-record screen a WINDOW record's opaque interior was painted below every field, so an earlier record's fields still showed through it. Each record now gets a stack layer (window box 2n, its fields / `*CHAR` border cells / ERRMSG line 2n+1) emitted as inline z-indexes, so a window hides the records before it and never its own content or a later record; a windowed record's fields take the window's own background instead of the darker screen-frame one. New `p15WindowInteriorMasking.test.js`. Still not covered: DDS OVERLAY/ERASE keyword semantics.
- **0.10.257** — P14 (Compare/overlay stacking): checked records now stack in the order they were selected with the current record on top, and a later record overwrites the cells under it instead of printing over them. Full overlay draws the checked records first and the current record last (it used to put the current record at the bottom); `resolveMultiScreen` flags `stacked` when 2+ records contribute and the screen gets a `dspf-stacked` class whose zero-specificity rule gives every field an opaque background (also applied to the primary screen above a dimmed backdrop); the compare checklist shows each checked record's layer number and the hint states the order. New `p14OverlayStacking.test.js`. Not covered: window interiors masking what is under them, and the DDS OVERLAY/ERASE keywords.
- **0.10.256** — I-121 (Cross-level; DATFMT/DATSEP/TIMFMT/TIMSEP value-domain slice): the values these four keywords accept (DATFMT *JOB/*MDY/*DMY/*YMD/*JUL/*ISO/*USA/*EUR/*JIS; TIMFMT *HMS/*ISO/*USA/*EUR/*JIS with no *JOB; DATSEP *JOB plus slash/dash/period/comma/blank; TIMSEP *JOB plus colon/period/comma/blank, no slash) were four hand-kept arrays in `webviewClientHelpers.js`. Each keyword's spec entry now carries `validValues` plus a citation, with `KeywordSpec.validValues` / `isValidValue` and `DspfWriter.dateTimeValidValues`; the Date/Time format panel builds its selects from them (the "unspecified" choice stays a UI concept). New `i121DateTimeValueDomainKeywordSpec.test.js` also ties the engine's DATFMT width table, the fixed-separator format lists and the panel labels to the same domain. Pure refactor, no behavior change.
- **0.10.255** — I-121 (Cross-level; CHECK option-code table slice): CHECK's spec entry now carries the full code domain in IBM's own three function groups (validity checking AB/ME/MF/M10/M10F/M11/M11F/VN/VNE, keyboard control ER/FE/LC/RB/RZ, cursor control RL/RLTB; 16 codes) with `KeywordSpec.checkCodeGroups` / `checkCodes` / `checkCodeGroup`. New `i121CheckCodeTableKeywordSpec.test.js` also ties every code other spec facts name for CHECK, and both editor panels' code lists, to the domain. Pure refactor, no behavior change.
- **0.10.254** — I-134 (Field; SNGCHCFLD / MLTCHCFLD / PSHBTNFLD layout parameters on the `commitEdit` path): only the Choice selection type and Push-button field panels refused `*NUMCOL` together with `*NUMROW`, a `*GUTTER` below 2, and (SNGCHCFLD / MLTCHCFLD only) a `*GUTTER` with neither `*NUMCOL` nor `*NUMROW`, so the raw keyword editor accepted all three. New `i134LayoutParametersGuard.test.js` (56 checks, including a real-webview part). Full suite: 203 files, 11,618 checks, zero failures.
